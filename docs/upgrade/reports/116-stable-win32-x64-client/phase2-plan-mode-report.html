Phase 2 Plan Mode 调研报告

日期：2026-05-15 ｜ 工作区：E:\Projects\Director-Code-batch\Director-Code-112-check ｜ 主题：Director native Plan、Claude Plan、ACP Plan 的统一策略

结论摘要

  • 本地 VS Code 主线的核心 Chat Mode 仍是 Ask、Edit、Agent。Plan 不是第四个全局 ChatModeKind，而是 Agent Host / Claude session 的配置状态。
  • Director 不能只“新增一个 xxx agent 配置文件”就完成 Plan Mode。真正需要的是 tool policy、权限继承、退出/审批路径、UI 状态和测试。
  • 推荐 Director v1 把 Plan 做成一个 session/mode profile：只读工具 + 计划输出 + 审批后切到 Edit 或 Agent。Claude 外部 Agent 直接映射 permissionMode: "plan"，ACP Agent 优先使用其 advertised session mode。
  • OpenCode/free-code 的关键经验是：Plan Mode 的 edit deny 必须传递给 subagents，否则子 Agent 可以绕过计划态限制。

VS Code 观察

本地 E:\Projects\sub-projects\vscode checkout 显示 package.json version 为 1.121.0。相关实现说明：

  • src/vs/workbench/contrib/chat/common/constants.ts：核心 ChatModeKind 只有 Ask、Edit、Agent。
  • src/vs/platform/agentHost/common/agentHostSchema.ts：Agent Host 有 interactive 和 plan 两种 session mode。Plan 描述为先生成计划，再选择如何执行。
  • src/vs/platform/agentHost/common/claudeSessionConfigKeys.ts：Claude permission mode 包含 plan，并把 auto approve/mode 等轴折叠到 Claude 自身 permission 语义。
  • extensions/copilot/src/extension/chatSessions/claude：Claude 集成会处理 ExitPlanMode，并通过 review plan UI 让用户 approve、approve and auto-edit、approve and bypass approvals 或反馈拒绝。

因此，VS Code 的模式更接近“Agent session 配置 chip”，而不是 chat framework 层新增 Plan 模式。

Director 推荐设计

Native Director Plan

  • 把 Plan 做成 Director-owned session/mode profile，而不是先强改 VS Code core ChatModeKind。
  • 工具权限：默认只允许 read-only tool layer，例如 read_file、list_dir、file_search、grep_search、get_errors、get_changed_files、view_image。默认拒绝 reviewable edit tools、terminal destructive 操作和目录创建。
  • 计划输出：第一版可直接返回 structured markdown；第二版可允许只写 .director/plans/*.md，但这仍要经过明确白名单。
  • 退出路径：Plan response 底部提供 Approve and Edit、Approve and Agent、Revise Plan、Cancel。Approve 后将计划和上下文带入 Edit 或 Agent。

Claude Plan

  • Claude SDK adapter 中设置 permissionMode: "plan"，并处理 ExitPlanMode / review plan tool。
  • 用户审批后可切到 acceptEdits 或 Director Edit/Agent session。不要让 Claude Plan 直接绕过 Director reviewable edit contract。

ACP Plan

  • 若 ACP agent 在 NewSessionResponse.modes 或 session update 中暴露 plan mode，调用 setSessionMode。
  • 若 agent 不支持 plan mode，Director adapter 仍应在 host bridge 层禁用 write/terminal dangerous capability，并注入 plan instructions。
  • ACP 的 plan session update 可以映射为 native Chat plan progress，而不必变成文件编辑。

建议：Plan Mode 作为跨 native/Claude/ACP 的 policy profile 来做。UI 表达可以先是 chat input chip 或 command，底层必须是一套可测试的 mode routing policy。

最小实现步骤

  1. 新增 DirectorChatMode.Plan 或独立 session config key，但先不要修改 VS Code core enum，除非现有 UI 无法表达。
  2. 扩展 directorChatModeRouting.ts，加入 Plan policy：read-only + plan output，明确拒绝 edit tools。
  3. 新增 Plan prompt/reminder，要求先理解、必要时提问、输出执行计划、等待审批。
  4. 新增 approve/revise/cancel UI action，审批后切入 Edit 或 Agent。
  5. Claude SDK adapter 映射 permissionMode: "plan"；ACP adapter 映射 setSessionMode 或 host-side fallback。
  6. 补充测试：Plan 不暴露 edit tools、Inline 不受影响、子 Agent 不能继承出 edit 权限、ExitPlanMode 审批能正确切换。

风险

主要风险：如果 Plan 只靠 prompt，模型或外部 Agent 很容易通过已有 edit/terminal 路径执行修改。必须在 tool registry、adapter bridge、subagent inheritance 三处都加限制。

  • 不要把 Plan 文件写入当成普通 edit tool，否则会触发 Chat Editing UI 的误导性审阅体验。
  • 不要让外部 ACP agent 宣称 plan 后仍保留 writeTextFile/terminal dangerous 权限。
  • 不要把 Plan 与 Ask 混同。Ask 是问答，Plan 是可审批的执行方案，后者需要状态机。
