结论摘要

  • 不建议把所有外部 Agent 强行标准化为 ACP。ACP 应作为通用外部 Agent 协议层，Claude Code 应优先走 @anthropic-ai/claude-agent-sdk TypeScript SDK 直连。
  • 本地 VS Code 主线代码显示，Claude Code 也是通过 Claude Agent SDK 接入，并且把 plan、permission、tool confirmation、session content provider 等能力映射到 VS Code 原生 Chat Session UI；这支持我们为 Claude 做专用 adapter。
  • vscode-acp 适合作为 ACP 进程、session、permission、mode/model 事件的参考，但它是独立 webview chat，不应作为 Director 最终 UI 架构。
  • Codex 在本地 VS Code checkout 中只看到核心 session type / UI 入口准备，未看到完整本地 Codex agent adapter。Director 可以先用通用 ACP 接 codex-acp 做 parity spike，再决定是否需要专用 Codex adapter。
  • 第一版目标可以低于“完全并入 Director 内部工具体系”：达到 VS Code 式外部 Agent session、权限确认、流式消息、文件编辑可审阅即可。

既有 Director 前情

旧 Phase 2 ACP 计划位于 .cursor/plan-04-phase2-acp.md，原始方向是将每个 ACP 外部 Agent 动态注册为 native chat agent，并通过 AcpAgentProxy、AcpServerConnection、ClientSideConnection、AcpClientImpl 把外部进程接入 VS Code Chat UI。

这个方向仍然成立，但现在需要按 116 replay 的现实收缩边界：当前 Director 已完成 Ask/Edit/Agent/Inline mode routing、read-only tools、reviewable edit tools 和 Chat Editing contract。新增 Agent 接入必须落回 replay patch，不能只改 vscode.generated。

ACP 仓库与协议能力

E:\Projects\sub-projects\vscode-acp 是一个 ACP Client VS Code extension，核心价值是展示了 ACP 的最小闭环：

  • AgentManager.ts 负责启动 agent 子进程。Windows 下使用 shell 以获得用户 PATH，这对 Director 包装 CLI agent 很重要。
  • ConnectionManager.ts 使用 @agentclientprotocol/sdk 的 ClientSideConnection 和 NDJSON stream 初始化协议能力。
  • AcpClientImpl.ts 实现 client 端的文件读写、terminal、permission request 和 session update。
  • SessionManager.ts 管理 newSession、prompt、setSessionMode、unstable_setSessionModel、auth retry。

ACP SDK 当前可表达 session modes、models、tool calls、tool call updates、plan entries、usage updates、auth、provider config 等。适合接入 Gemini CLI、OpenCode、Hermes、Qwen、Codex ACP wrapper 等通用 agent。

但 vscode-acp 使用独立 webview chat，并且文件写入直接走 vscode.workspace.fs。Director 不应照搬这部分 UI 和写文件方式，而应把 ACP session update 映射到 native Chat progress 和 Phase 3 reviewable edit contract。

VS Code 主线实现观察

用户提到的 VS Code 当前版本为 120。本地 checkout E:\Projects\sub-projects\vscode 的 package.json 显示为 1.121.0，可视作 120 之后主线代码。相关发现如下：

  • src/vs/workbench/contrib/chat/browser/agentSessions/agentSessions.ts 定义了 Claude 和 Codex session provider。Claude 描述明确提到 Claude Agent SDK。
  • src/vs/workbench/contrib/chat/common/constants.ts 中核心 ChatModeKind 仍是 Ask、Edit、Agent，没有独立核心 Plan mode。
  • src/vs/platform/agentHost/common/agentHostSchema.ts 定义了 agent host session mode：interactive 与 plan。因此 Plan 更像 session config，而不是全局第四种 chat mode。
  • extensions/copilot/src/extension/chatSessions/claude 下的实现通过 @anthropic-ai/claude-agent-sdk 接 Claude Code，并把 SDK 消息分发为 VS Code ChatResponse、tool confirmation、external edit tracking、ExitPlanMode review。
  • Codex 在该 checkout 中主要体现为 core session type 和 UI provider label，没有找到类似 Claude 那样完整的本地 adapter。后续应单独验证实际安装环境中的 Codex extension 或 ACP wrapper。

推荐架构

建议抽出一层 Director-owned external agent abstraction，而不是把 ACP、Claude SDK、未来 Codex SDK 写进 chat contribution 主流程。

层级 职责 第一版边界
ExternalAgentRegistry 注册 Claude SDK、ACP、未来 Codex adapter；暴露 displayName、capabilities、mode/model 状态。 只管理外部 Agent，不混入 LLM provider/model registry。
ExternalAgentSession 统一 start、resume、sendPrompt、cancel、setMode、setModel、dispose。 输出标准事件：markdown、thinking、tool call、permission、file edit、plan、usage、error。
ClaudeAgentSdkAdapter 直接调用 TS SDK，映射 Claude permission modes、Plan Mode、canUseTool、MCP/plugins、session resume。 不经过 ACP。
AcpAgentAdapter 管理 ACP child process、NDJSON connection、auth、session mode/model、permission request。 用于 OpenCode、Hermes、Gemini、Codex ACP wrapper 等。
ChatProgressBridge 把 adapter events 映射到 native Chat response 和 reviewable edit contract。 达到 VS Code 级体验，不要求外部 Agent 完全调用 Director 内部 tool registry。

建议实施顺序

  1. 先建立外部 Agent registry 和统一 session event model，只接入一个 mock adapter 做 native Chat progress 验证。
  2. 接入 Claude TS SDK adapter，完成 prompt、stream、cancel、permission、Plan Mode、文件编辑 review 映射。
  3. 接入 ACP adapter，先验证 OpenCode 或 Hermes，再验证 Codex ACP wrapper。
  4. 把 mode/model 选择收敛到 chat input session config，而不是复用 LLM 模型选择器。
  5. 再决定 Codex 是否需要专用 adapter。若 ACP wrapper 已满足 VS Code parity，可暂不专门实现。

风险与验证

风险：外部 Agent 能写文件、跑终端、调用子 Agent。Plan Mode 和权限必须在 host bridge 层兜底，不能只靠 prompt 或 agent 自觉。

  • Windows CLI spawn/PATH/auth 环境需要专门 smoke。
  • Claude SDK npm 包推进很快，需要版本 pin 和 adapter contract test。
  • ACP unstable_setSessionModel、provider config 仍不稳定，不能作为 Director provider 管理核心。
  • 所有最终代码要回写 replay patch，并跑 profile-scoped replay validation。
