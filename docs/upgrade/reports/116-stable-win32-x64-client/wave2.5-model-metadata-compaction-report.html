模型信息展示

好改。Director 已经在 registry model entry 保存 maxInputTokens、maxOutputTokens、capabilities，设置页模型行也已有第二行 .dc-model-meta。需要扩展能力 schema 和统一 formatter。

低风险

Reasoning Effort

中等改动。VS Code 116 已有 effort button 机制，关键是 Director 要生成 per-model variants，并在 Agent/LM request 中读取 modelConfiguration.reasoningEffort 后映射到各 provider 原生参数。

3.1 新增/扩展 Director 模型元数据形状

3.5 Reasoning effort 请求链路

需要同时覆盖 Chat Agent 和 Direct Language Model API 两条路径。

路径当前状态改法
Chat Agent DirectorCodeAgent.invoke 收到 request.modelConfiguration 但未读取。 解析 request.modelConfiguration?.reasoningEffort，用 selected model variants 映射成 AgentEngineConfig.thinking 或 provider request options。
Direct LM API DirectorCodeModelProvider.sendChatRequest 参数名为 _options，当前未使用 options.configuration。 读取 options.configuration?.reasoningEffort，传给 provider。
Provider abstraction CreateMessageParams 只有 Anthropic/Gemini 风格 thinking。 扩展为 reasoningEffort? 或 providerOptions?。OpenAI provider 映射 reasoning_effort 或对应 API 选项；Anthropic/Gemini 继续映射 thinking/thinkingConfig。

最小推荐 variants:

  • OpenAI o/gpt reasoning family: low, medium, high，必要时 minimal。
  • Anthropic thinking-capable models: high = 16k budget, max = min(output - 1, 31,999)。
  • Gemini 2.5: high = 16k budget, max = 24,576/32,768 budget。
  • Codex OAuth models: 如果 backend 支持 effort，就从 endpoint/Catalog 给 variants；否则先只显示 Thinking capability，不暴露 effort。

4. 会话上下文压缩深挖

4.1 Director 当前压缩完整流程

  1. 每个 Agent loop turn 开始时，调用 shouldAutoCompact(messages, model, state, maxInputTokens)。
  2. 估算 tokens 使用 UTF-8 byte / 3.5 的粗估；阈值是 maxInputTokens - 13_000 或 getContextWindowSize(model) - 13_000，最低 8k。
  3. 压缩前 strip image blocks，防止总结请求吞掉大量图片 tokens。
  4. buildCompactionPrompt 把所有历史线性化: string message 截 5,000 chars，text block 截 3,000 chars，tool result 截 1,000 chars。
  5. 调用 compact model 或主模型，maxTokens: 8192，system prompt 要求保留上下文、决策、文件修改、工具输出、当前状态。
  6. 压缩成功要求 summary 长度至少 10，并且新两条消息估算 tokens 小于原始 tokens 的 90%。否则视为失败，保留原历史并累计失败次数。
  7. 成功后把整段 history 替换为: 
    User: [Previous conversation summary]

<summary>

[End of summary - conversation continues below]

Assistant: I understand the context from the previous conversation. I'll continue from where we left off.
  8. Agent 继续当前 turn；请求前再对 tool result 做 micro-compact。
  9. 如果 provider 报 prompt too long 且本次还没 compact 过，会 compact 一次，回滚 turn counter 并 retry 当前 turn。
  10. 请求结束时 DirectorCodeAgent 把 engine messages 写入内存 replay snapshot；下一轮如果 VS Code rich history 缺工具细节，会优先用 replay snapshot。

4.2 与 OpenCode 的差距

能力OpenCodeDirector 当前Wave 2.5 建议
保留最近上下文 默认保留最近 2 个 user turns，并按 token budget 裁剪。 不保留 tail，全部总结掉。 加 tailTurns=2 与 preserveRecentTokens=2k-8k 的轻量 selection。
压缩边界 synthetic compaction user part + summary assistant message。 普通 user summary + ack assistant，且主要存在 engine/replay snapshot。 先保留现状，增加更明确 compact_boundary progress/metadata；完整 first-class boundary 留给后续。
旧工具输出 pruning 可标记旧 tool output compacted，保护最近工具。 只有请求前 micro-compact，不持久化。 Wave 2.5 可不做持久 pruning，但 tail 里应避免吞掉最后一次重要工具结果。
自动继续 compact 后可生成 synthetic continue user message。 当前 compact 在同一 turn 内继续执行，不需要额外 continue message。 不建议改变，避免影响 VS Code chat request 生命周期。
可配置 compaction.auto/prune/tail_turns/preserve_recent_tokens/reserved。 只有全局 context window 和 compact model。 至少增加内部常量或 hidden setting；公开设置可后置。

4.3 推荐的 Wave 2.5 压缩改造

  1. 接入真实模型窗口: 在 DirectorCodeAgent.invoke 解析出 selected registry model 后，如果用户没有设置全局 directorCode.ai.maxInputTokens，把 registryModel.maxInputTokens 传给 AgentEngineConfig.maxInputTokens。
  2. 保留最近 tail: 在 compactConversation 中拆分 head 与 tail。summary prompt 只总结 head，返回 [summary user, ack assistant, ...tail]。
  3. tail selection: 从最后往前找最近 N 个 user turns，预算默认 min(8_000, max(2_000, floor(usable * 0.25)))，复刻 OpenCode 思路但实现更轻。
  4. 避免重复总结 summary: 如果第一条消息已经是 [Previous conversation summary]，再次 compact 时把旧 summary 当 previous summary anchor，并总结 summary 之后的 head。
  5. 进度可见: 成功 compact 时现有 compact_boundary 可扩 metadata: original tokens、new tokens、tail messages count、used compact model。

8. 风险清单

  • 模型能力假阳性: 如果本地 catalog 误标 image/audio/video，用户会以为能用但 provider 报错。需要 metadataSource 和 unknown 显示。
  • OpenAI-compatible 多样性: 同一个 OpenAI-compatible endpoint 对 reasoning_effort 支持差异很大。默认只给已知模型/用户 override 开 variants。
  • VS Code configuration schema 生命周期: picker effort config 存在 language model service 内，model identifier 变化会丢配置。Director identifier 已包含 provider instance id，符合预期。
  • 压缩 tail 角色顺序: 必须保证 summary user + ack assistant 后追加的 tail 仍是 provider 可接受的 user/assistant 交替历史。
  • Replay landing: 最终源码改动必须回写 004-director-agent-engine.116.patch，不能只改 vscode.generated。

9. 推荐接受标准

  • Director Settings 模型列表每个模型名称下方显示 context/output/input modalities/tool/thinking/effort summary。
  • Chat model picker hover tips 显示 OpenCode 风格的模型详情；VS Code 自带 max context section 仍正常。
  • 支持 variants 的模型在 picker 旁出现 Thinking Effort UI，选择值能进入 Agent request 和 direct LM request。
  • OpenAI/Anthropic/Gemini/Codex provider 对不支持的 effort 不发送错误字段。
  • 自动 compact 使用 selected model 的真实 max input；压缩后保留最近 tail；prompt-too-long fallback 仍可 retry。
  • Clean materialize 后至少跑 replay validators、TS compile/transpile、相关 unit tests 和一轮 browser model picker/settings smoke。
