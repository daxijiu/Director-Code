VS Code 116 48 个工具来源与 Director 对齐策略

本报告基于本地 116 materialized source，对用户在 VS Code UI 看到的 48 个工具逐项核对： 哪些是 VS Code core 可直接复用，哪些是 Copilot 扩展贡献工具只能复刻 schema/name，哪些是 Director 已有能力的对应项， 以及哪些需要延期或先确认来源。

结论摘要

  • runSubagent 可以直接对齐复用。它不是 Copilot 扩展实现，而是 VS Code core 的 RunSubagentTool。Director 与上游该文件无实质 diff；差异只来自 Director Agent Engine 选择何时把它放进 model-facing allowlist。
  • 浏览器交互工具 clickElement / openBrowserPage / runPlaywrightCode 等也是 VS Code core 工具，代码在 src/vs/workbench/contrib/browserView/electron-browser/tools/，Director tree 中代码与上游一致。它们可直接复用，但需要单独确定安全策略和 workbench.browser.enableChatTools 默认行为。
  • 终端与任务工具 runInTerminal、getTerminalOutput、createAndRunTask 等是 VS Code core 工具，Director 已直接复用；当前差异主要是两处用户可见品牌文案。
  • createFile / createDirectory 与 Director 当前 create_file / create_directory 是能力对应，但不是直接复用：上游同名工具来自 Copilot 扩展，Director 已有 reviewable implementation。推荐保留 Director 实现，后续若切名到 camelCase，应只对齐 model-facing name/schema。
  • apply_patch、replace_string_in_file、multi_replace_string_in_file 不建议并入 editFiles。Copilot 的 editFiles 在 package 里是 placeholder；Director 的 reviewable edit primitives 是实能力，应继续保留 Director-owned 口径。
  • renderMermaidDiagram 不是 Copilot 工具。它由 extensions/mermaid-chat-features 注册，Director tree 中也存在并注册，所以用户测试“116 能用”是合理的。旧报告里“Director 未 allowlist”只说明 Director Agent Engine 默认不会把它下发给模型，不等于扩展/UI 不可用。
  • githubTextSearch 在本地 VS Code 116 source、Director source、Copilot package 里都没有静态注册命中。它更像运行时动态来源，例如 MCP/GitHub 相关扩展贡献；实现前需要抓取实际 tool source/id。

判定准则

分类 含义 维护策略
直接复用 工具实现位于 VS Code core 或仍保留的内置扩展；Director 可以通过 ILanguageModelToolsService 注册的真实工具直接调用。 只维护 Director registry / allowlist / 模式策略 / 品牌文案，尽量不 fork 工具实现。
对应但不 1:1 Director 已有相同或接近能力，但上游 UI 名来自 Copilot 扩展，不能在去 Copilot 化产品里直接依赖 Copilot runtime。 保留 Director implementation；可以按 toolReferenceName 对齐名称和常用参数，必要时接受 alias。
延期/不实现 能力依赖 Copilot 服务、商业登录、Notebook/Workspace/Command 高风险 mutation，或暂不属于当前 Director coding-agent 主线。 不暴露给模型；需要产品策略、安全策略和 schema 报告后再做。
来源待确认 静态源码中找不到注册，可能是运行时 MCP/扩展/用户 profile 贡献。 先抓 runtime raw tool snapshot，再决定是否复用、封装或忽略。

关键核对点

runSubagent

实现来源是 src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts。 对比 layers/vscode 与 layers/director 后该文件无 diff；因此不存在 “Director 自己实现的 runSubagent 与 Copilot 不一致” 这个问题。 Copilot 的 ToolName.CoreRunSubagent 只是引用 core tool id/reference，不是 Copilot 扩展提供实现。

Director 当前在 directorToolRegistry.ts 中把 runSubagent 限定为 Agent mode、需要 pre-approval。 如果后续要更贴近 VS Code UI 的工具集合，保留这条 registry entry 即可，不需要重写工具。

renderMermaidDiagram

上游和 Director 都有 extensions/mermaid-chat-features/package.json 的 languageModelTools 注册，src/chatOutputRenderer.ts 里调用 vscode.lm.registerTool('renderMermaidDiagram', ...)。 这个工具返回 Mermaid markdown block，并附带自定义 renderer details。

Director Agent Engine 当前只通过 getDirectorToolAllowlist() 生成模型工具定义； renderMermaidDiagram 没有 registry entry，所以默认不会进入 Director Agent 的 tools 数组。 用户看到它可用，可能来自 UI raw tool picker、非 Director 路径，或 Mermaid markdown renderer 本身能渲染模型输出的 Mermaid code block。 推荐后续增加一个明确的 registry entry，而不是自实现 Mermaid 工具。

Copilot extension 工具

vscode.generated/layers/director/vscode/extensions/copilot 不存在，说明 Director runtime 不能直接调用 Copilot extension 的 tool implementation。 这些工具只能把 toolReferenceName、常用 input schema 和用户体验作为参考，然后由 Director 自己实现或明确延期。

推荐工具治理方案

波次 范围 动作 风险点
Tool Wave A Director 已有 read/create/fetch/github 能力 逐个输出 schema 报告，然后把 model-facing 名称对齐到 readFile、listDirectory、fileSearch、textSearch、problems、changes、viewImage、createFile、createDirectory、fetch、githubRepo。 不能丢现有能力；路径参数要统一 absolute vs workspace-relative；githubRepo 必须说明不支持 Copilot 远端索引。
Tool Wave B VS Code core direct reuse 保持 runSubagent、terminal/task、todo、askQuestions；为 renderMermaidDiagram 加明确 registry entry；browser 组按安全策略整体纳入。 browser tools 会真实操作网页；runPlaywrightCode 需更谨慎的确认/日志策略。
Tool Wave C Copilot-only deferred tools 不直接复用 Copilot extension runtime。Notebook、memory、newWorkspace、runCommand、vscodeAPI、codebase 等单独立项。 这些工具大多绑定 Copilot 服务、workspace mutation 或外部文档/索引能力，贸然暴露会增加维护面和安全面。
Tool Wave D 动态来源工具 增加 runtime raw tool snapshot 报告，特别确认 githubTextSearch 的 source/id/schema。 没有来源就无法判断许可、实现依赖和安全策略。
