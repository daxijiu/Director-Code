范围

  • 保留 Director 当前已经暴露给模型的能力。
  • 对已确认是 VS Code core 或保留内置扩展实现的工具，尽量直接复用上游实现。
  • 对于工作区读取、搜索、图片、GitHub context、文件/目录创建等 Director 已有能力，保留 Director 实现，只在必要时对齐 model-facing 名称和 accepted schema。
  • apply_patch、replace_string_in_file、multi_replace_string_in_file 本阶段不改名、不并入 Copilot editFiles。
  • 不依赖、不打包、不恢复 Copilot extension runtime。

接受后实施顺序

  1. 工具 registry / direct-reuse wave：加入 browser tools 和 renderMermaidDiagram registry entry；extensions 仍隐藏到 Phase 5。
  2. 读取/搜索/context facade wave：readFile、listDirectory、fileSearch、textSearch、problems、changes、viewImage。
  3. 写入/创建 facade wave：createFile、createDirectory。
  4. web/repo legacy exception facade wave：fetch、githubRepo。
  5. 每个工具切到新 model-facing 名称的同一波，移除旧 snake_case 或 legacy model-facing 名称；不保留双名兼容期。

需要你确认的点

  • 接受 fetch 仅作为 URL/file fetch；query 只作为意图文本接受，不代表 Copilot web-search。
  • 接受 githubRepo 仅作为有限 read-only repo context；远端 indexed search 返回受控 unsupported/limited 结果。
  • 接受 browser tools 在 Phase 3 作为 Agent-only direct reuse；交互/修改类工具需要 Director-level pre-approval，页面读取/截图在非当前用户打开的 Director browser session 时需要 domain/session approval。
  • 接受 extensions 来源上是 direct reuse，但在 Phase 5 product/gallery/marketplace 文案策略和商业/品牌 grep gate 前保持隐藏。
