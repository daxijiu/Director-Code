# Tool Facade Research

Status: accepted

Profile: `116-stable-win32-x64-client`

Date: 2026-05-14

Source plan: `docs/upgrade/director-thin-layer-refactor-plan-v2.md`

Accepted source report: `docs/upgrade/reports/116-stable-win32-x64-client/tool-source-and-strategy-analysis.html`

This report is the accepted Phase 3 hard gate. Tool facade cutovers, direct-reuse allowlist changes, browser tool exposure, and model-facing tool renames may proceed in the implementation waves defined below.

## Scope

- Preserve current Director model-facing capabilities.
- Reuse VS Code core or retained extension tools directly where the accepted source report classifies them as direct-reuse candidates.
- Keep Director-owned implementations for current workspace read, search, image, GitHub context, and create tools; only align model-facing names and accepted schemas where useful.
- Keep `apply_patch`, `replace_string_in_file`, and `multi_replace_string_in_file` unchanged in this phase. They are Director-owned edit primitives and are not part of Copilot `editFiles` parity.
- Do not depend on, package, or restore the Copilot extension runtime.

## Implementation Order After Acceptance

1. Tool registry/direct-reuse wave: add registry entries for browser tools and `renderMermaidDiagram`; keep `extensions` hidden until Phase 5.
2. Director facade wave for read/search/context tools: `readFile`, `listDirectory`, `fileSearch`, `textSearch`, `problems`, `changes`, `viewImage`.
3. Director facade wave for write/create tools: `createFile`, `createDirectory`.
4. Director facade wave for web/repo legacy exceptions: `fetch`, `githubRepo`.
5. Remove old model-facing snake_case or legacy names in the same wave as each cutover. No dual model-facing compatibility period.

## Open Acceptance Points

- Accept `fetch` as URL/file fetch only, with optional `query` ignored for retrieval and no Copilot web-search implication.
- Accept `githubRepo` as limited read-only repo context only, with controlled unsupported output for remote indexed search.
- Accept browser tools as Agent-only direct reuse in Phase 3, with Director-level pre-approval for mutation/interaction tools and domain/session approval for page read/screenshot outside the current user-opened Director browser session.
- Accept `extensions` as direct-reuse source but hidden until Phase 5 product/gallery/marketplace policy and grep gate.
