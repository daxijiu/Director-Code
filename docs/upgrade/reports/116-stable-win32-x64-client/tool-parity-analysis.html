VS Code 48 工具与 Director 工具面差异分析

日期：2026-05-14。比较对象是用户给出的 VS Code UI 48 个工具，以及当前 116 Director 模型可见 allowlist。

用户列表里的 runlnTerminal、typelnPage、viewlmage、getProjectSetuplnfo 看起来是 I/l 字形混淆；本报告按 VS Code/Copilot 源码中的 runInTerminal、typeInPage、viewImage、getProjectSetupInfo 归类，并在表格中保留原始写法。
48 VS Code UI 工具总数
10 Direct 直接复刻：Director 暴露同名模型工具
12 Partial 对应但不完全一样：能力相近，名称/策略/实现不同
26 Missing：VS Code 有，Director 当前没有模型可调用等价物

判定口径

本报告比较的是“模型可见工具面”。如果上游源码存在某工具，但 Director registry 将它标为 defer、hide 或没有 registry entry，就按 Director 不暴露处理。

直接复刻指 VS Code UI 的工具名和 Director 模型名相同，并且当前 Agent mode 可以调用。对应但不完全一样指 Director 有相近能力，但采用 snake_case 名称、Director-owned 安全实现、Chat Editing review flow、不同确认策略，或能力边界比 VS Code 原工具更窄。他有我们没有指 Director 当前没有模型可调用的等价能力；个别项有弱替代会在备注里写明。

23 getNotebookSummary Missing 无 Director 当前没有 Notebook cell 摘要/元数据读取工具。

25 readFile Partial read_file 能力对应，但 Director 使用工作区边界校验和大文件截断策略；模型名不同。
26 terminalLastCommand Direct terminalLastCommand 同名保留，Agent-only read。
27 terminalSelection Direct terminalSelection 同名保留，Agent-only read。
28 viewlmage / viewImage Partial view_image 能力对应图片查看，但 Director 工具受工作区路径限制，并提供文本元数据 fallback。

43 runCommand Missing 无 上游 run_vscode_command 可执行 VS Code command；Director 当前没有通用 command bridge。
44 vscodeAPI Missing 无 上游扩展开发 API 文档检索工具；Director 当前没有该专用知识检索工具。

46 githubRepo Partial github_repo 能力方向对应，但 Director v1 是 minimal read-only GitHub context；远端 indexed search、PR/issue workflow 不在范围内。
47 githubTextSearch Missing 弱替代：github_repo Director 没有独立 GitHub text search；当前 github_repo 明确不覆盖远端 indexed search。
48 renderMermaidDiagram Missing 上游扩展有注册，但 Director 未 allowlist Mermaid extension 注册了该 LM tool；Director registry 没有 entry，因此 Director 模型工具面不暴露。

直接复刻清单

这些工具在用户给出的 VS Code UI 列表和 Director allowlist 中使用同一个模型可见名称，主要集中在 Agent-only 的任务、终端、规划、用户询问工具。

  • runSubagent
  • createAndRunTask
  • getTerminalOutput
  • killTerminal
  • runInTerminal
  • sendToTerminal
  • terminalLastCommand
  • terminalSelection
  • todo
  • askQuestions

对应但不完全一样清单

这些工具的能力方向基本对应，但 Director 做了命名、边界、确认策略或实现层面的收敛。

  • createDirectory -> create_directory
  • createFile -> create_file
  • editFiles -> apply_patch / replace_string_in_file / multi_replace_string_in_file
  • problems -> get_errors
  • readFile -> read_file
  • viewImage -> view_image
  • changes -> get_changed_files
  • fileSearch -> file_search
  • listDirectory -> list_dir
  • textSearch -> grep_search
  • fetch -> vscode_fetchWebPage_internal
  • githubRepo -> github_repo

VS Code 有但 Director 当前没有

浏览器自动化工具

clickElement, dragElement, handleDialog, hoverElement, navigatePage, openBrowserPage, readPage, runPlaywrightCode, screenshotPage, typeInPage。

Notebook 工具

createJupyterNotebook, editNotebook, runNotebookCell, getNotebookSummary。

VS Code/Copilot 专用能力

codebase, searchResults, extensions, getProjectSetupInfo, installExtension, memory, newWorkspace, resolveMemoryFileUri, runCommand, vscodeAPI, githubTextSearch, renderMermaidDiagram。

其中 extensions、installExtension、newWorkspace 在 Director registry 中能看到被登记过的影子项，但状态是 defer 或 hide，不属于当前模型可调用工具。

Director 有但用户给出的 VS Code 48 列表没有

Director 工具 分类 说明
apply_patch Director-only surface 显式 patch 原语；VS Code UI 48 中以 editFiles 聚合展示，而 Director 单独暴露。
replace_string_in_file Director-only surface 精确字符串替换原语，走 Chat Editing review flow。
multi_replace_string_in_file Director-only surface 批量精确字符串替换原语，走 Chat Editing review flow。
runTask Director-only surface 执行已有 task；用户给出的 48 列表只有 createAndRunTask。
getTaskOutput Director-only surface 读取 task 输出；用户给出的 48 列表未列出。
task_complete Director-only surface Director Agent loop 的任务完成信号。
usages Director-only surface 基于 vscode_listCodeUsages 的代码使用点查询；用户给出的 48 列表未列出。
artifacts Director-only surface 会话 artifact surfacing 工具。
artifactRules Director-only surface 会话 artifact 规则更新工具。
vscode_get_confirmation Director-only surface Director 保留的通用确认 helper。
vscode_get_confirmation_with_options Director-only surface Director 保留的选项式确认 helper。
vscode_get_modified_files_confirmation Director-only surface 修改文件确认 helper，保留到 reviewable edit contract 完整替代直接 mutation path。
vscode_get_terminal_confirmation Director-only surface 终端工具确认 helper。

说明：如果按源码内部工具而不是用户给出的 UI 48 列表比较，上游 Copilot 也有若干低层编辑原语；这里的“我们有他没有”严格按用户提供的 VS Code UI 48 个工具面判断。
