120 Agents Window Wave 3 两项调研汇报

日期：2026-05-20｜范围：path ownership 与 custom headers / Claude proxy 边界｜性质：只读调研汇总

总判断：这两个点都不需要继续卡成 open decision。Path ownership 不需要大范围接管上游目录；custom headers 是 Director Provider Registry 既有安全边界问题，Claude Agent v1 只需要确保 secrets 不跨进 AgentHost。

结论 1：Path Ownership

不要 broad-prefix 大目录

不建议把 replay 分类 broad 到 src/vs/sessions/** 或 src/vs/platform/agentHost/**。当前工作是桥接和适配，不是接管整棵上游 surface。

保留 004 / 005 exact allowlist 为主 narrow adapter island
结论 2：Custom Headers

不是 Claude 新问题

Custom headers 已经是 Director Provider Registry 的既有能力，也已经被普通 Director chat 使用。Claude AgentHost 会扩大暴露面，所以 v1 的关键是不要把 raw header/key/token 传进 AgentHost。

既有 Registry 风险 Claude 用 proxy 边界隔离 SecretStorage 迁移后续跟踪

一、Path Ownership 调研结果

当前 generate-director-patches.mjs 对 AgentHost 和 Agents Window 的覆盖很窄：已有 005 覆盖 workbench 的 agentSessions/**，但 vs/sessions 只显式覆盖少量文件；004 对 platform AgentHost 也基本没有覆盖生产 Claude runtime。

推荐分类策略

  • 继续使用现有 004-director-agent-engine.120-insider.patch 和 005-director-chat-built-in-mode.120-insider.patch。
  • 不要新增 Wave3 专用 patch stage。
  • 不要 broad 到 src/vs/sessions/**，因为它混有 account、setup、Copilot provider、AgentHost provider、remote/tunnel、session service、customization 等多个上游面。
  • 不要 broad 到 src/vs/platform/agentHost/**，因为它混有 common protocol、node runtime、Electron starter、Claude adapter、shared CAPI、mock/test 等多类内容。
  • 允许窄前缀：src/vs/platform/agentHost/node/claude/** 进 004；如果新增 Director bridge，可用 src/vs/platform/agentHost/node/director/**；如果新增 Director sessions facade，可用 src/vs/sessions/contrib/directorSessions/**。

预计路径落点

Replay stage 策略 预计路径
005 exact allowlist copilotChatSessionsProvider.ts、account.contribution.ts、sessionsSetUpService.ts、baseAgentHostSessionsProvider.ts、localAgentHostSessionsProvider.ts、localAgentHost.contribution.ts、必要的 sessions service 文件。
004 exact allowlist agentHostMain.ts、agentHostServerMain.ts、agentService.ts、agentSideEffects.ts、common/agentService.ts、electronAgentHostStarter.ts。
004 narrow prefix src/vs/platform/agentHost/node/claude/**。这是 Claude adapter island，边界清楚，适合窄前缀。

执行影响：Segment 0 仍然要更新 generate-director-patches.mjs，但更新方式应克制。不要为了省事把整个上游 sessions/AgentHost 树变成 Director-owned。

二、Custom Headers / Claude Proxy 调研结果

VS Code 120 的 Claude AgentHost 形态确实是本地 proxy：Claude SDK / Claude Code 只连本地 Anthropic-compatible proxy；proxy 再连真实后端。上游真实后端是 Copilot/CAPI。Director 应该复用这个壳，把 proxy outbound 换成 Director Provider Registry。

VS Code 120: Claude SDK / Claude Code -> local Anthropic-compatible proxy on 127.0.0.1 -> Copilot/CAPI Director Wave3 v1: Claude SDK / Claude Code -> Director local proxy -> Director Provider Registry selected Anthropic/Anthropic-compatible provider

最小实现形态

  • 复用 Claude SDK path 行为：用户安装/配置 Claude Code 后出现相关选项，保持 VS Code 语义。
  • 恢复或重做生产 Claude AgentHost 注册，但注册的是 Director-compatible 后端。
  • 保留 ClaudeAgent、ClaudeAgentSdkService、session lifecycle、event rendering、permission UI 等上游行为。
  • 替换 ICopilotApiService / CAPI outbound，改成 Director-owned Anthropic Messages transport/proxy。
  • proxy 按 session 绑定 provider snapshot：session id、provider instance、model、base URL、headers、auth 都在 Director proxy 边界内解析。
  • SDK-visible model id 和 Director routing id 分开。不要把 director-code/<instance>/<model> 直接塞给 Claude SDK。

Custom headers 的判断

Custom headers 不是 Claude Agent 新引入的问题。当前 Provider Registry 已有 headers 字段，Provider Settings UI 已支持输入，普通 Director chat/model provider 也会使用这些 headers。

风险在于：这些 headers 现在作为普通 registry state 持久化，并且可能覆盖内建认证头。

问题 结论 Wave3 v1 处理
是否要先全量迁 SecretStorage 不作为 Claude bridge 的前置条件 单独跟踪 Provider Registry hardening。
headers/key/token 是否能进 AgentHost 不能 AgentHost/SDK 只拿 local proxy URL + opaque bearer/nonce。
真实 provider URL/key/headers 在哪里解析 Director proxy 内部 proxy 内按 session-bound provider snapshot 发请求。

执行影响：Claude bridge v1 不需要先重构整个 Provider Registry secret 模型，但必须保证不把 raw custom headers、API key、OAuth token、env credential 或 provider baseURL 放进 AgentHost root state、session config、model metadata、session index 或日志。

对执行计划的最终落点

  • 两个原 open decisions 已经收敛，不再阻塞第一批实现。
  • Segment 0 先做 replay path classification，但分类策略是 exact allowlist + narrow adapter island。
  • Segment 3/4 维持 VS Code proxy 形态，不做 Director 自己的一套 Claude runtime。
  • Provider Registry custom headers hardening 作为后续安全任务，不混进 Claude AgentHost v1 的主线。
  • Customization 和 Claude history/restore 的方向保持：以 VS Code 等价行为为基线，只在 Provider/Auth/Proxy/UI 接入上 Director 化。
