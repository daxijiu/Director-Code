Date: 2026-05-19 Scope: research synthesis No implementation changes Target: 120 Insider replay baseline

一句话结论

工作量可控，但边界要画准。 不需要重做 Agents Window，也不需要重做 Claude UI。要做的是 Director Sessions Bridge：让新窗口消费 Director 已有的 Provider Registry、Auth、Model、Session、Customization 和 Tool policy。

保留

Agents Window 是重要体验，应该作为跨工作区 session 管理中心保留。

复用

Claude AgentHost 的 session、UI、permission prompt、event rendering 和 SDK-native tool 行为可以复用。

替换

上游 Copilot/CAPI provider、auth、model discovery、account status 不能直接复用。

分阶段落地

A. Policy Inventory先保留窗口，同时阻止破碎账号状态和未授权 provider 暴露。
B. Registry Bridge把 Provider Registry、visible models、auth status 接入 AgentHost/Agents Window。
C. Claude Runtime注册 Claude AgentHost provider，替换 Copilot/CAPI auth、model、proxy。
D. Session Index让 IDE 与 Agents Window session 列表一致，避免 synthetic workspace 造成空列表。
E. Customization/Tools统一 skills/instructions/plugin 来源和 AgentHost tool policy。

主要风险

Provider ID 兼容

直接改掉 default-copilot 或 agent-host-* 可能破坏已有 resource/session。优先 facade/wrapper。

Auth 边界

AgentHost utility process 不能直接拿 workbench secret/OAuth 服务。需要明确 IPC/config/proxy handle。

Tool policy 绕过

Claude SDK-native tools 不等于 Director tool registry。v1 可以接受，但 permission/session policy 要 Director 控制。

Customization 泄漏

vs/sessions 有独立 skills/root/source，必须显式 allow/deny。

Session 分裂

Agents Window synthetic workspace 不会自然看到主 IDE chat history。需要共享 session index。

Replay 漂移

这些改动容易散落在 generated tree。要先补 stage/path classification，再生成 replay patch。

建议的下一步

把 Phase 2 Wave 3 正式扩展成 Director Sessions Bridge + Claude AgentHost Provider。第一刀不要追求全量 session 同步，先让 Agents Window 保留可用，同时移除破碎 Copilot/GitHub account 状态和未受控 Claude/provider 暴露；随后接入 Director Provider Registry 和 Claude runtime。
